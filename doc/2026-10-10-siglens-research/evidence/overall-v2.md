## Affected scenario walkthroughs

The following walkthroughs inspect the proposed v2 text and editable diagrams. They are not executable simulations. Selection follows the mandatory trust, evidence-preservation and duplicate-delivery goals plus the review's concrete counterexamples.

**T8/T10, startup and executable replacement.** Start with a research plan and a configured X route. The trusted executor checks selection, validates the protected real executable/build/digest and effective configuration, then requires the C8 OS boundary before supplying dedicated Grok credentials or source data. A changed build/configuration or unavailable boundary yields typed failure; it does not reuse a prior profile result. The actual Q1 canary started under a profile-only configuration, so v2 cannot mark that configuration ready. A storage/archive caller can consume unavailable-X without exposing its store; the shared launcher, credential provisioning and affected packaging remain Q1-dependent. Inspecting these guards establishes the intended ordering, not that any production OS policy implements it.

**T6/T7, stale snapshot and cross-runner ownership.** Start with A holding a claim. A commits intent and the destination may accept a publication, but B receives a snapshot taken before intent. A's stop evidence proves only that A cannot start further sends. B declares recovery origin, keeps sending disabled and converts the copied non-delivered claim to unknown. No-intent, copied epoch/store ID, elapsed time and an empty remote search cannot open retry. A positive matching receipt resolves delivered; positive proof of no publication plus serial ownership can resolve unsent. Missing the target pair entirely follows the same recovery gate. This rejects the review's duplicate-send path. A malformed/missing receipt cannot preserve delivered status, and missing canonical content blocks transmission. No remote reconciliation, backup restore or crash test was executed.

**T3/T6, finalization crash and renderer change.** Start with one validated draft revision and pinned V1 evidence. Before commit, any content/transaction failure leaves the draft. After commit, the ID, finalization time, canonical bytes and hashes are fixed even if file output fails. A concurrent or later same-revision finalize returns that identity and copies its bytes; a new renderer is not invoked to replace them. Claim and begin_send require valid materialization. A changed or missing file is repaired from committed bytes, not fetched or rerendered. A content correction deliberately starts a new draft revision/edition. Wrapper timing and attachment routing cannot redefine canonical payload hashes. This removes the v1 hash/receipt ambiguity while preserving V1 access after V2; no filesystem or concurrency execution is claimed.

**T2, interrupted run and old writer.** Start with an in-flight upstream request and a crashed run owner. Resume atomically advances the run epoch; old-epoch writes are rejected. A possible provider-side completion remains uncertain and can incur another call on retry, as F8-AC4 requires. This run rule grants no publication permission; delivery still follows C7. The developer must choose and test recovery mechanics under Architect task review (TR4).

**T4, pinned model identity.** Start with a Discovery nomination, evidence/rubric versions and explicit model configuration. A moving alias or missing pin is a configuration failure before a call, not evidence of a completed scoring attempt. After a real call, missing/mismatched returned identity is saved as invalid response evidence; it cannot yield a valid four-score result. The genuine-failure path remains subject to the product's Agent takeover rules. Valid matching responses retain low-confidence data and the original threshold arithmetic. The main design does not invent a supported pinned ID; primary protocol and actual response evidence are still required before review-adapter coding. No Jev call ran here.

**T5/T9, cross-domain explicit inclusion.** Start with an active current event whose origin is another domain but which the reader explicitly included in the designated daily domain's tracking set. tracking_snapshot selects it by membership. An ordinary or paused event is not active; a pending/cancelled merge or split keeps the prior current pointer and choices. A confirmed correction atomically changes current revisions and memberships. The C5 wording therefore preserves F5-AC7/E11/E14 without granting automatic inclusion. No two-day research trial or archive mutation ran.
