# 结构化研究报告

阅读入口：[MVP 规格](mvp-spec.md) · [文档索引](../README.md)。本文保留专题细节与历史提案；当前范围以主规格及后续有效决定为准。

状态：Named-Topic 交付、时间 / 不确定性规则，以及第十四轮 JSON / Markdown 文件分工已确认；章节与数据结构仍为建议，尚未实现。

## 已确认契约

- 用户可以直接指定主题，Agent 制订计划后由 CLI 执行研究，无需经过提名与候选审阅。
- Named-Topic 默认尝试全部经 doctor 验证配置完成的渠道，用户可用 CLI 参数选择需要的渠道；来源无结果、失败与未配置分别记录，失败按既有规则降级。
- 交付结构化研究报告，默认使用英文，保留原始证据链接。
- 默认重点研究最近七天的新进展；研究创建时固定起止窗口，续跑、补证和刷新不自动移动范围。可引用窗口外背景材料，但须明确标记。
- 可以交付“目前无法确认”的研究结果；不因用户提供了主题名就假定相关产品、事件或说法已成立。
- Agent 负责语义综合；CLI 管证据、执行状态与可程序校验的要求。
- 支持多轮研究：Skill 指导 Agent 根据证据缺口决定继续，由 CLI 执行新的结构化计划；由 Agent 判断问题是否已充分回答；MVP 不设资源额度，不设置已获确认的固定无进展轮次阈值。

## 建议的报告结构

1. **Summary**：直接回答研究问题，概述主要发现与关键不确定性。
2. **Scope and Questions**：研究对象、时间窗口、研究问题和范围边界。
3. **Recent Developments**：窗口内具体变化，区分事件时间与材料发布时间；每项关联原始证据。
4. **Analysis and Evidence**：按研究问题组织发现、相互支持或矛盾的材料；区分直接证明、来源自述、Agent 推断和仍无法确认之处。
5. **Background**：理解新进展所必需的旧材料，明确日期和背景身份；没有相关内容时可省略。
6. **Limitations and Open Questions**：证据缺口、冲突、渠道失败造成的局限，以及下一步可研究的问题。
7. **Evidence References**：正文可定位的引用与原始链接；覆盖统计采用 CLI 记录，不由 Agent 估算。

章节不要求填满，也不强制固定发现数或字数。无法确认主题时，概要明确该结果，分析说明已检查的范围、找到的材料与尚缺哪些证据；不能为完整排版虚构 Recent Developments。

## 时间与结论的边界

窗口外材料用于背景，不能因为本次采集就被列为新事件。新发布材料描述旧事件时同样需要区分事件时间与发布时间。Discovery 中事件时间未知的材料先作为待核查候选保留并尝试补证，补证后仍无法确定时间则说明缺失依据，保留在待核查候选中，不计入最终近期主题卡；这一规则不改变 Named-Topic 可交付无法确认结果的决定。

“目前无法确认”描述某个研究问题或具体陈述的证据状态，不等同于“已证明不存在”。来源不可用、确实查无结果、材料互相矛盾是不同情况，应分别说明。一份报告可以部分事项已确认、部分无法确认，不必强迫整个对象具有单一真假标签。

## 文件与职责建议

已确认人读报告与主题卡使用 Markdown，结构化研究数据与状态使用 JSON。默认保存取得的正文文本及实际引用的片段与上下文，附原始链接、取得时间和材料类型，只有摘要时如实标记；网页 HTML 与完整 API 响应为可选调试资料。CLI 提供本地读写、引用校验与执行状态，Agent 生成综合内容；Skill 指导外部工具将必要文件交给后续 Agent。研究 CLI 不增加跨机器打包或传输功能。

报告完成状态与结论确定性分别记录。中断或渠道失败时保留已取得的阶段性产物。Q71 已确认续跑复用成功操作，只继续失败或未完成操作；Q72 已确认校验失败时保留草稿并返回具体缺口，不标为正式交付。已允许的降级不自动构成交付失败，仍需满足其他交付规则。
