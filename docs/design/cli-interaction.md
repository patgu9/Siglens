# CLI 调用与产物契约草案

阅读入口：[MVP 规格](mvp-spec.md) · [文档索引](../README.md)。本文保留专题细节与历史提案；当前范围以主规格及后续有效决定为准。

状态：第二十八轮确认首次研究或相关配置变化时自动运行 doctor，指定渠道未包含 Web 时不使用 Brave 兜底；第二十六轮 Q70–Q72 已确认默认 JSON、复用成功结果并继续失败 / 未完成操作，以及校验失败时保留草稿并返回缺口、不标为正式交付。具体命令名和数据字段仍为建议，尚未实现；以下命令仅示意，不可执行。

## 设计目标

CLI 提供可独立调用的能力，允许外部 Agent 在调用之间读取材料、提交判断或调整计划。它不在内部启动生成式 Agent，不等待某个特定模型，也不要求安装 Multica。Skill 负责将这些能力组成用户需要的工作流。

全部支持渠道默认启用，Discovery 与 Named-Topic 均默认尝试经 doctor 验证配置完成的渠道；用户可以通过 CLI 参数选择需要的渠道。研究窗口、英文检索与输出、Brave 兜底、五档 Jev Score、无额度控制等沿用 [当前设计](discovery-mvp.md)。

## 建议操作面

| 操作 | 示意命令 | 输入与结果 |
| --- | --- | --- |
| 阅读使用指南 | `siglens guide` / `siglens guide review` | 返回能力说明、前置条件、输入示例、错误与继续操作方法 |
| 查看接口结构 | `siglens schema plan` | 返回当前版本的结构化计划格式；Agent 不必猜字段 |
| 验证渠道 | `siglens doctor` | 验证各渠道配置与必要依赖，返回结果及缺失；首次研究或相关配置变化时自动触发，探测细节待设计 |
| 查看渠道状态 | `siglens sources` | 展示最近验证记录及当前配置，不把缓存检查结果当作实时服务保证 |
| 建立研究 | `siglens init` | 保存入口、领域或指定主题、创建时解析的固定窗口和本地产物位置，返回研究标识 |
| 采集 / 补证 | `siglens collect --plan plan.json` | 校验并执行 Agent 提交的计划，保存材料、基础去重及渠道状态 |
| 读取研究 | `siglens inspect` | 获取当前材料索引、候选、审阅及执行状态；正文按引用读取 |
| 提交 Agent 产物 | `siglens submit --kind nominations` 等 | 保存提名、事件合并、证据绑定、选择记录或综合稿；不同 kind 使用各自 schema |
| Jev 审阅 | `siglens review` | 对已提交候选及其材料执行审阅，保存四维 Score 与淘汰建议 |
| 检查及形成交付 | `siglens validate` / `siglens finalize` | 检查 Agent 产物，生成或保存最终 Markdown 与对应结构化结果 |

这里区分只读、采集、模型调用和 Agent 提交，便于工作流给不同 Agent 分工。业务能力仍是提名、候选审阅、主题研究与交付；命令不必一一对应四个阶段。

CLI 不从证据自动撰写研究结论。最终 Markdown 的语义内容由 Agent 提交，CLI 可按已确认字段渲染或保存，并检查结构及引用。指南包括默认工作流示例，但不能把外部工作流选择权收回 CLI。

## 一次调用的返回

Q70 已确认默认返回 JSON。建议 stdout 返回一个结构化 JSON 结果，包含：契约版本、研究标识、当前状态版本、操作是否完成、是否部分成功、产物引用、可处理的错误与后续操作提示。进度放 stderr，避免日志破坏 JSON。显式人读格式仍为可选提案，尚未确认；交付文件仍按既定 JSON / Markdown 分工保存。

操作成功、材料覆盖完整、研究问题得到充分回答是三个不同事实。例如本次选择包含 Web、Reddit 失败且 Brave 仅找到摘要时，本次操作可完成并返回部分结果，但必须保留降级和正文缺失。状态名称与退出码待接口细化，不用一项 success 覆盖所有含义。

返回结果提供产物索引与必要摘要，不重复输出全部取得的正文。Agent 根据证据引用读取相应材料及上下文；这种分步读取不改变默认保存已取得正文的要求。

## 计划与状态建议

结构化计划包含本次查询目的、所关联主题 / 证据缺口、渠道、查询或已知 URL、时间范围及适配器支持的参数。查询语义由 Agent 生成；CLI 验证格式、渠道能力和研究约束，再执行。正文抓取与 Brave 降级应留下实际执行记录，不因为计划最初指定平台就把间接结果标为平台直连。

Q78 已确认创建研究时固定窗口；后续计划、续跑和刷新不得自动移动该起止范围，需要新的近期窗口时创建新研究。

计划是一次有限操作的说明；是否继续追加计划由 Agent 决定。不因没有额度限制而把 collect 实现为自动发现新问题并无限翻页研究的循环。分页边界属于本次查询的适配器参数，不能包装为已撤回的全研究请求额度。

同一研究内默认复用相同操作的已有结果、显式刷新才重新请求已确认。建议操作身份基于已解析的输入、材料版本及相关配置，而非仅基于查询字符串；Jev 审阅还需关联量表与模型配置。具体散列和版本机制属于实现细节，不是新产品选择。

## 中断后继续

在单次调用过程中保存已完成的操作和阶段性产物。Q71 已确认 Agent 再次执行同一计划时，复用已有成功结果，只继续未完成或失败的操作；不要求对成功操作一并刷新。健康空结果也是成功结果，不能为了填数量反复重试。

连接中断而无法判断服务是否已处理请求时，记录执行结果不确定；不能声称重试恰好只执行一次。尤其模型请求可能已经执行但响应未保存，再次调用可能重复发生费用。MVP 不控制额度，仍应诚实记录已知执行状态。

读取状态与 Agent 分析可并行，研究状态变更仍串行。Agent 提交时建议带基于的状态 / 材料版本；遇到过期输入返回可处理冲突，不覆盖新状态。不存在后台自动续跑或 CLI 调度下一个 Agent 的要求。

## 草稿与正式交付

Q72 已确认校验失败时保留草稿、返回具体缺口，不标记为正式交付。允许保存阶段性产物；通过交付校验后才标为正式交付。建议同时保留之前已通过的版本，具体版本组织待设计。

建议作为阻断错误：引用的证据不存在、必需字段缺失、Discovery 近期卡没有事件时间依据、最终卡数超过配置上限、Discovery 无 Jev 审阅记录且无不可用降级记录。具体格式以已确认业务约束建立，不用模型低分代替校验错误。

渠道故障、只有一个一手来源、合法的 Jev 降级、Named-Topic 得出目前无法确认，不自动阻断交付；这些按既有规则明确记录。CLI 检查证据引用与时间依据是否存在及窗口匹配，陈述是否被材料实质支持仍由 Agent 判断，不能承诺结构校验等于事实核验。

## 第二十六轮确认范围

- Q70：CLI 默认返回 JSON；用户未进一步确认额外人读输出模式。
- Q71：续跑复用成功结果，只继续失败或未完成的操作；刷新成功结果仍遵循既有显式刷新规则。
- Q72：校验失败保留草稿、返回具体缺口，不标记为正式交付。

字段名称、退出码、命令名称和状态冲突细节仍待接口设计，不因本轮三项行为获采纳就视为全部示意接口已冻结。
