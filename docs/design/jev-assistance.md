## 已确认的边界

- CLI 调用 Jev，保留分维度判断；宿主 Agent 最终选择与综合。
- 四维价值判断仅使用 Jev Score，不增加 unknown 或可评分性 Choice。保留服务返回的概率分布与 confidence 作解释，不据此自动屏蔽、重加权或替换分数。证据不足与调用失败另行记录。
- Jev 不可用时允许降级，并明确标记缺失。
- 提名阶段不调用 Jev；在提名后、强化调研前，CLI 调用 Jev 审阅候选、识别垃圾信息并提供研究价值的多维评分，Agent 选择强化调研对象。
- 研究价值采用四个维度：实质变化、具体性与信息量、潜在影响、后续研究空间。第二十二轮 Q65 已确认使用五档量表；具体等级描述与评分质量仍待评测；四维全低于中点的建议规则已由 Q68 / Q69 确认，未确定组合权重；候选审阅时使用已有材料，不能把未做的强化调研当作已完成。
- 判断依据 CLI 取得的原文片段及上下文；必须尝试跨渠道核查，不强制两个独立来源。一手材料可独立支持其直接证明的事项。
- CLI 采集和基础去重；Agent 合并事件、命名并绑定证据形成提名，再由 CLI 调用 Jev。
- 社区对某模型可能即将发布的猜测类信息剔除；不作为待核实主题卡交付。缺乏具体新事项的个人求助 / 入门问答、空泛感想、纯推广及空内容按内容判断排除，不凭句式机械过滤。
- 有明确事件线索但仅有摘要或搜索片段时，允许进入补证，标记“初始证据不足”；这不等于确认事实，也不豁免纯猜测剔除。
- Agent 负责结构化研究计划；研究检索和主题卡输出使用英文。
- 数量、时间窗口和证据链接等由 CLI 管理与校验。

## 官方事实及设计含义

| 官方事实 | 对本项目的含义（设计推论） | 来源 |
| --- | --- | --- |
| Jev 输出 Choice、Score、Noul 等结构化判断，不生成自由文本 | 不要求它给主题命名、写摘要或编造判断理由；这些仍由 Agent 负责 | [Introduction](https://docs.typesafe.ai/introduction) |
| Choice / Score 的 confidence 由结果概率分布推导，Noul 无独立 confidence | 高 confidence 不等于事实已证实；分别保留判断、概率分布和适用的 confidence | [Confidence](https://docs.typesafe.ai/confidence) |
| Score 使用有明确描述的有序等级，返回等级编号的概率加权均值 | 不把任意 0–100 分当作客观价值；先定义能区分的语义等级 | [Score](https://docs.typesafe.ai/primitives/score) |
| 同一请求的问题分别根据同一 state 作答，不读取其他问题的答案 | 可以一起问独立维度；依赖前一步输出的判断需要新的状态或后续请求 | [Primitives](https://docs.typesafe.ai/primitives) |
| 日期比较、计数与数值计算属于已知弱项；无关上下文会影响判断 | 7 天过滤与 21 张上限放在 CLI；评估输入仅含相关材料 | [模型限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13) |
| 官方引用核查示例对给定陈述与原文判断支持、反驳或未涉及 | 核查单位应包含明确陈述及可追溯文段；支持关系不能升级为现实世界的真实性保证 | [引用核查](https://docs.typesafe.ai/cookbooks/citation_check) |

同一请求的判断隔离不意味着结果统计独立，不能直接把不同问题的概率相乘。官方示例阈值及样例准确率不能直接作为 Siglens 的验收标准。

## 历史四维草案及接下来需要区分的判断

以下是早期四维英文问题方向，不是已批准的提示词或 schema。第五轮已确定拆分研究价值；“可否研究”和“研究价值有多高”需要分别表达，不把垃圾信息排除规则与价值排序混成一个总分。

| 维度 | 可判断的窄问题 | 不应混入的问题 |
| --- | --- | --- |
| 领域相关性 | Does the supplied item directly concern the defined domain? | 是否热门、是否为真实发布 |
| 具体新进展 | Does the item describe a concrete change, release, finding, or event? | 是否在最近 7 天内；是否从未有人发现过 |
| 证据支持 | How does this source passage relate to this specific claim: supports, contradicts, or does not address it? | “整个主题是真的还是假的” |
| 研究价值（仍待拆分） | Does the evidence identify a changed capability, a concrete consequence, or a testable unresolved question? | 没有标尺的“值得研究 87 分” |

研究价值的示例问题含多个信号，实际调用时应按用户选定的信号拆成独立问题。模型判断不能填补缺失来源；没有相关材料应记录缺失。

## 判断输入与留痕建议

- 输入保留领域定义、明确候选陈述、带证据 ID 的原文片段及上下文、来源元数据；不只发送 Agent 已加工的摘要。
- 标记材料为正文、摘要、搜索片段或截断内容；片段中未出现某句话不代表原文不存在该句，更不能直接判为捏造。
- 同时保留支持和反驳材料；不要让选择文段的步骤预先掩盖冲突。
- 将抓取材料视为数据，避免让其中的推广措辞或指令改变评分规则；这也是后续评估用例的一部分。
- 留存实际模型版本、问题 / 标准版本、输入证据引用、返回分布与 Agent 最终决定，以便比较误判和复核覆盖。
- 使用英文检索与判断，但不把搜索结果只有标题的情况伪装成已读完整来源。

## 用来检验设计的假设案例

这些案例不是新闻事实，也不是模型实测结果。

| 输入 | 应能表达的差异 |
| --- | --- |
| 某机构官方宣布 Model Z 发布，几乎无人转发 | 高相关、具体进展、可支持发布事实；低互动不能自动淘汰 |
| 多篇社交帖子猜测 Model Z 即将发布，无公告 | 属于用户明确要求剔除的猜测类信息；高相关或高互动不能抵消 |
| 官方公告说“进入封闭测试”，转发称“向所有人开放” | 支持封闭测试，不支持全量开放，不能一并标为发布成功 |
| 半年前的发布稿今天大量转发 | 内容可能有价值，但转发时间不能替代事件时间 |
| 一篇新论文声称疗法有效 | 可以支持“作者发表了该研究 / 报告了结果”，不直接证明疗效已被独立确认 |
| 请求仅取得摘要，核心条件出现在未取得的正文 | 标记证据不足，不因缺失上下文武断判错 |

## 第二十二轮：五档量表

Q65 确认四个研究价值维度采用五档，参考调研问卷的五点量表。建议对外展示为 1–5：很低、较低、中等、较高、很高；这些短标签用于阅读，每档须有独立、具体的维度描述，不能只给模型“低 / 中 / 高”。各维描述草案见 [评分参考](../research/last30days-junk-scoring.md)。档数已确认，标签和描述是待评测建议。

建议使用程度量表回答“这一维度体现到什么程度”，不把材料是否充分混成同意程度。中点 3 表示中等程度；第二十三轮 Q66 已确认材料不足单独记录 unknown，低档也不能作为缺失值。Q67 要求参考上游设计淘汰规则，不设总分淘汰线的建议未被采纳为最终政策。

依据：Pew 的问卷方法强调有序选项顺序本身传递含义；Jev Score 官方要求等级有具体描述，每个问题只判断一个维度，并用实际样例检验描述。这支持五档分别锚定可观察情况，但不证明五档天然优于其他档数，也不代表模型已通过校准。[Pew 问卷设计](https://www.pewresearch.org/writing-survey-questions/)、[TypeSafe Score](https://docs.typesafe.ai/primitives/score)。

接入注意：当前 Jev Score 的等级索引从 0 开始，五档对应 0–4；返回 score 是等级索引的概率加权均值，可能为小数。建议保留原始结果，若对外使用 1–5 则显式映射，不把小数均值宣称为模型选出的整数档。概率分布、置信度、显示档位规则与量表版本需在接口设计中明确；unknown 不作为第六个有序等级加入 Score。

## 技术澄清：直接使用 Jev 的维度分数

用户进一步询问能否直接使用 Jev 输出的概率权重作为维度分数。核查结论：Score 返回的 score 已是该维度各档索引的概率加权均值，可以直接作为连续维度分数；不是把某一个档位的概率或 confidence 当作价值分数。若对外展示 1–5，使用 display_score = score + 1；五档仍用于定义语义锚点，无需强制舍入成整数档。

例如，显示档位 3 的概率为 0.3，档位 4 的概率为 0.7，其余为零，则原始 score 为 2.7，对外分数为 3.7。这是说明公式的假设样例，未运行模型。

建议各维保存原始 score、probabilities、confidence 及量表版本，展示连续分数并向 Agent 提供分布。confidence 描述分布集中程度，不表示该维度的重要性或事实正确率，不建议用它乘分数来自动惩罚不确定性。不同分布可能产生相同均值，不能只留均值而丢掉分布。来源：[Score](https://docs.typesafe.ai/primitives/score)、[Confidence](https://docs.typesafe.ai/confidence)，2026-09-28 核查。

档位概率是维度内部的权重，不是四个维度之间的组合权重。直接使用 score 的建议不自动决定四维总分或淘汰线；第二十三轮 Q66 已确认 unknown 单独标记，Q67 要求参考上游设计淘汰规则。五档是有序评价标准，连续分数用于辅助比较，不据此声称相邻档的现实价值差距已被校准。

## 第二十三轮：unknown 与淘汰规则

unknown 单独标记已确认。建议按维度表达：某维无法判断不使其他有效分数作废；unknown 不参与低分条件计算，不填 0、最低档或中档。具体 JSON 可用状态加空分数表示，但字段名尚未冻结。即使服务返回数值，材料不足时也不能把它当成有效评分；原始响应可留作诊断，判断所依据的材料与缺失原因需关联保存。unknown 也不等同低 confidence，后者可能来自相邻档难区分。

用户要求参考 last30days 设计淘汰规则。建议保持资格排除、低价值建议、补证等待和数量未入选分开，由 Agent 确认语义结论，CLI 执行可验证规则；不移植固定互动门槛或两个 source 的强制要求。具体条件和例子见 [候选淘汰规则](candidate-elimination.md)；第二十四轮 Q68 已采纳四维均可判断且全部低于中点 3 时提出淘汰建议、Agent 最终确认，并通过样例评测调整。

## 第二十四轮：unknown 在 Jev 机制中的含义

unknown 独立于分数的政策合理，但需要由应用层表达每维是否有足够依据评分；它不是 Score 原生的第六档，也不能直接由低 confidence 推导。候选整体证据薄弱不代表四维全部 unknown：已取得文本的具体性可能可评，而实际影响仍缺少依据。具体分析、同请求 Choice + Score 的可选接入方式与评测建议见 [unknown 分析](jev-unknown.md)。接入方式尚未获采纳。

## 第二十五轮：采用 Score，撤回 unknown

Q69 已明确抛弃 unknown，仅使用 Jev Score，替换 Q66。此前额外可评分性 Choice 的建议不实施，历史 [unknown 分析](jev-unknown.md) 不再作为当前设计要求。

每维依据已取得的材料及其上下文进行五档评价，直接使用返回的连续 score；对外 1–5 映射为 raw score + 1。CLI 只作响应结构、类型、数值范围等契约校验，不基于“可评分性”屏蔽合法模型分数。probabilities 和 confidence 保留供 Agent 解释，不生成评分 unknown，也不作为分数乘数。

四维成功返回并通过响应校验，且未舍入的展示分全部 < 3，产生低价值淘汰建议，由 Agent 最终确认；阈值继续通过样例调整。证据薄弱可能影响 Jev 分数，Agent 应结合独立证据状态判断是否仍值得补证，不以低分建议替代最终选择。

超时、模型不可用或无效响应属于执行失败，不能补造零分、最低分或中间分来满足四维条件。研究的“初始证据不足”、事件时间未知及待核查候选状态继续保留；取消的是额外评分 unknown 层。
