# 可组合研究能力草案

阅读入口：[MVP 规格](mvp-spec.md) · [文档索引](../README.md)。本文保留专题细节与历史提案；当前范围以主规格及后续有效决定为准。

状态：已记录至第二十九轮；Discovery 与 Named-Topic 默认渠道覆盖、多轮研究与时间未知候选的保留已确认，浏览器兜底与额度控制不纳入 MVP。具体命令和数据格式尚未冻结。名称用于讨论，不是已实现命令。

## 能力分组建议

| 能力 | 输入 | CLI 负责 | Agent / 外部工作流负责 | 产物 |
| --- | --- | --- | --- | --- |
| 提名 | 领域、窗口、Agent 研究计划；随后提交 Agent 提名 | 校验计划、七渠道采集、基础去重；校验并保存提名 | 规划、合并事件、命名、绑定初始证据 | 提名主题卡及证据包，明确未经完整审阅 / 核查 |
| 候选审阅 | 提名与原文片段、上下文 | 调用 Jev、保留资格判断与分维度评分、缺失状态 | 解释判断、选择强化调研对象；Jev 故障时按规则接手 | 审阅记录与 Agent 选择记录 |
| 主题研究 | 用户指定主题或 Discovery 选定主题、可选的已有证据、Agent 研究计划 | 执行研究计划、取得原文与上下文、核查并保存证据与结果 | 提出研究问题、解释证据关联、决定是否继续 | 研究证据包及核查尝试记录 |
| 交付 | 研究证据包、Agent 撰写的结果 | 校验格式、引用存在性、时间依据等可检查要求并保存 | 综合证据、写明已知与未知及后续问题，最终选择 | Discovery 主题卡；Named-Topic 结构化研究报告 |

“产出提名主题卡”是业务能力边界，不代表 CLI 自行完成语义命名。一次能力使用可以包含取材料、外部 Agent 判断、提交产物等多个调用；CLI 不需要一直等待某个 Agent，也不在内部启动生成式 Agent。

采集、读取、提交、校验、继续执行等可作为能力内部操作或可复用原语。最终命令数量应在输入输出和状态确定后决定，避免现在将四个能力误定为四个一次性命令。

第二十五轮之后的具体操作、指南与产物契约建议见 [CLI 交互草案](cli-interaction.md)；Q70–Q72 已确认默认 JSON、中断后复用成功操作并继续失败 / 未完成操作、校验失败保留草稿并返回缺口。具体命令仍为草案，不是已实现接口。

## 证据与交付文件

默认保存取得的正文文本，以及实际引用的片段与上下文、原始链接、取得时间和材料类型；只有摘要时明确标记。网页 HTML 与完整 API 响应为可选调试资料。JSON 保存结构化研究数据与状态，Markdown 保存主题卡和研究报告。

渠道专用采集不可用时，仅在本次选择包含 Web / Brave 且其验证可用的条件下允许通过 Brave 定向检索，并区分内容所在渠道、实际检索方式和原文是否取得。详见 [渠道与证据契约](source-evidence-contract.md)。

## 自由编排与研究质量

已确认两条入口：

- Discovery：领域计划 → 提名 → Jev 候选审阅 → Agent 选择 → 主题研究 → 主题卡。
- Named-Topic：用户指定主题 → Agent 研究计划 → 主题研究 → 研究结果，不要求提名或候选审阅产物。

用户可以自行分配 Agent、并行处理主题或反复补证。建议以产物资格和可检验前置条件约束结果，不强制按某条固定命令历史执行。CLI 继续校验 Agent 研究计划；直接研究不等于省略计划与证据处理。

例如：可保存只有提名的中间产物，但不能把它标作满足有限补证要求的最终主题卡；跨渠道核查尝试可以失败且明确降级，一手材料仍只能支撑直接证明的事项。证据充分性含语义判断，CLI 的结构校验不能保证其事实正确。

Discovery 不允许主动跳过 Jev，仅不可用时可明确降级，由 Agent 接手。直接研究用户指定主题不属于跳过候选审阅。建议记录研究入口及主题来源，避免自动发现的候选仅被改标签就丢失审阅要求；其校验强度与外部用户指令的表达方式待定。

Jev 不可用的具体分类与降级记录格式仍待确认。第十轮明确无事件时间的材料先保留为待核查候选并尝试补证；第十一轮进一步确认补证后仍未知的候选继续保留并说明缺失时间依据，不计入最终近期主题卡。不得把“不可用”自行扩大为为了节省成本而主动关闭。

## 候选审阅规则

研究价值按实质变化、具体性与信息量、潜在影响、后续研究空间四维判断；领域相关性、纯猜测、初始证据状态单独记录。垃圾信息按内容判断，不能因问句或自荐形式机械淘汰具体新事件。

有明确事件线索但仅取得摘要或搜索片段的候选，允许标记“初始证据不足”进入补证；缺失材料不等于垃圾，也不等于事实已确认。纯猜测仍排除。五档量表已确认；Q69 取消评分 unknown 和可评分性 Choice，直接使用 Jev Score。四维 Score 均成功返回并通过响应校验、全部低于中点 3 时，按 Q68 提出淘汰建议，由 Agent 最终确认。具体等级描述与该阈值通过样例评测调整，详见 [淘汰规则](candidate-elimination.md)。评分详见 [Jev 辅助判断](jev-assistance.md)。

## 采集覆盖与多轮研究

第十轮 Q37 与第二十一轮 Q64 分别确认 Discovery 和 Named-Topic 默认尝试所有已配置渠道。默认覆盖不等于保证每个渠道都有结果，来源失败与健康空结果仍需区分；未配置渠道不能伪装成查询后零结果。Q73 已进一步要求全部支持渠道默认启用，经 doctor 验证后仅允许完成配置的渠道参与，用户可用 CLI 参数指定需要的渠道；Q76 要求首次研究或相关配置变化时自动运行 doctor；Q77 明确指定渠道列表未包含 Web 时不使用 Brave 兜底。

支持多轮研究。Q78 已确认研究创建时固定窗口，续跑、补证及刷新沿用该窗口；新的近期范围需新建研究。Skill 指导 Agent 读取当前证据、识别缺口、决定是否追加查询并提交下一轮结构化计划；CLI 校验和执行该计划、保存结果，不自行选择下一位 Agent 或发动研究循环。继续研究沿用既有研究约束与产物，允许 Agent 显式调整计划；由 Agent 判断问题是否已充分回答；同一研究内相同操作默认复用已有结果，Agent 显式要求刷新才重新请求。MVP 不设采集次数或 Jev 费用额度，保留阶段性产物。同一研究的 CLI 状态变更串行执行，Agent 可并行分析材料。

Named-Topic 不采用由 Agent 按相关性默认缩减渠道的建议；Agent 仍负责各渠道的具体查询计划。全部尝试不等于每个渠道必须有结果，也不取消已有结果复用与显式刷新规则。

## MVP 范围与研究深度

第八轮 Q31 已将直接 Named-Topic 研究纳入首版。例如用户指定“GPT-6”，可以直接调用主题研究能力，不必先从领域发现该主题。这个示例不构成对该产品存在、发布或能力的事实确认。

这替换此前“Named-Topic 仅预留”的范围限制。Discovery 的有限补证交付保持不变，Comparable 仍为后续扩展。

第九轮确认 Named-Topic 交付结构化研究报告，默认重点研究最近七天的新进展；允许引用窗口外背景材料，必须明确标记，不能计作窗口内新事件。用户可以研究证据不足的主题，允许交付“目前无法确认”的研究结果；报告应说明查到什么及尚不能确认什么，不把研究对象存在或相关说法成立当作前提。

报告结构建议与上游交付参考见 [结构化研究报告](research-report.md)。研究是否充分由 Agent 判断；MVP 无额度控制，未采纳固定无进展轮次自动结束。详见 [研究资源与执行约束](research-limits.md)。

## 产物交接

第九轮明确：交接属于 Skill 层，而非研究 CLI 功能。使用 Multica 时依赖 Multica CLI 传递；不使用 Multica 时，可以通过宿主 subagent 的协作能力完成。研究 CLI 只提供普通本地产物读写、引用与格式校验，不实现跨目录 / 跨机器运输，也不新增专用研究包导入导出功能。

此前提出的可携带研究包与导出 / 导入能力未采纳，已撤回。产物需要的稳定引用、数据格式和恢复状态仍属于研究本身，具体定义待定。Skill 须指导外部工作流传递后继任务实际需要的材料，不能假设不同运行器天然共享目录。

## MVP 兜底范围

第十九轮 Q60 确认 MVP 不实现浏览器兜底，仅使用 Brave 作为采集降级路径；Q77 进一步限定，指定渠道列表未包含 Web 时不使用 Brave 兜底。既有普通 HTTP 正文获取继续保留；无法取得正文时明确标记摘要或缺失。Jev + browser_use 的 [探索记录](browser-fallback.md) 仅作后续参考，不新增首版能力或依赖。
