# Siglens MVP 规格

整理日期：2026-09-29。决定基线：设计访谈第一至第二十九轮（截至 Q78）。

本文是当前 MVP 的汇总入口：第 1–9 节整理已确认范围，第 10 节列出待定设计，第 11–12 节为从需求推导的验收清单与实现顺序建议。整理不新增产品决定，不将专题草案自动提升为已确认契约。历史回答见 [设计访谈](discovery-mvp.md)，全部材料见 [文档索引](../README.md)，领域术语见 [CONTEXT.md](../../CONTEXT.md)。

**当前阶段：Stage 1 (Think) 与 Stage 2 (Plan) 已完成，[实施方案 (Implementation Plan)](implementation-plan.md) 与 [事件档案与连续日报](event-archive-and-daily-brief.md) 已获批准 (APPROVED)，即将进入 Stage 3 (Build) 产品实现。** 仓库已有完整加固实施方案、架构拓扑与验收矩阵；实现代码与产品测试将在 Stage 3 展开。文中的能力均为实现目标。

## 1. 产品目标与范围

Siglens 帮助用户在明确关注领域内发现值得进一步研究的具体事件或实质新进展，并保存支持或质疑相关陈述的可追溯证据。研究价值与事实是否已确认分别表达；Trending 诉求不自动代表已测得历史增长趋势。

产品形态为 **Skill + 独立 CLI**。CLI 采用 Python 3.12+，优先提供 uv tool 安装方式，自带 Agent 操作指南，默认返回 JSON。Skill 指导宿主 Agent 使用和组合研究能力；Multica 不是 CLI 的必需依赖。

| 入口 | 必需输入与默认范围 | 首版交付 |
| --- | --- | --- |
| Discovery（主题发现） | 必须指定领域；默认最近 7 天，窗口可配置 | 有限补证后的英文主题卡；数量可配置，默认最多天数 × 3 张 |
| Named-Topic（指定主题研究） | 用户直接指定具体主题；默认重点研究最近 7 天新进展 | 英文结构化研究报告；可以得出“目前无法确认” |
| Comparable（对比研究） | 多个明确对象 | 未来扩展，首版不实现完整工作流 |

默认英文检索，研究输出同样使用英文并保留原始证据链接。未要求首版增加其他语言模式。7 天默认最多 21 张卡；质量不足允许少于上限，不要求每天 3 张，也不将其作为原始采集量、提名数或每渠道配额。

## 2. 时间与研究边界

- 创建研究时解析并固定起止窗口；续跑、补证与显式刷新沿用同一窗口。需要“截至现在的最近 N 天”时创建新研究。
- 按具体事件或实质新进展的时间判断近期性，不能用采集时间、再次转发时间替代事件时间。
- 窗口外材料可用于背景，须明确标记，不能计作窗口内新进展。
- Discovery 候选事件时间未知时，先保留待核查并尝试补证；仍无法确定时保留候选、说明缺失依据，不计入最终近期主题卡。
- Named-Topic 的调查对象不必已获证实。报告可描述时间或事实尚不能确认，但不能把“未确认”写成“已证明不存在”。

窗口长度、交付数量和采集资源是不同约束。MVP 不设采集次数或 Jev 费用额度。

## 3. 职责边界

| 主体 | 负责的工作 |
| --- | --- |
| Skill / 外部工作流 | 指导选择 Agent、模型、推理档位与运行器；安排任务、研究轮次及产物交接；可使用 Multica CLI 或宿主 subagent |
| Agent | 生成结构化研究计划；合并事件、命名并绑定证据；作语义判断与最终选择；识别证据缺口、决定是否继续；撰写综合结果 |
| Siglens CLI | 校验并执行计划；采集、基础去重、保存证据与研究状态；调用 Jev；提供指南；校验可程序检查的交付要求 |
| Jev | 在 Discovery 候选审阅中辅助识别垃圾信息、提供分维度研究价值判断；不负责主题命名或生成报告 |

CLI 提供本地产物读写与校验，不负责 Agent 调度、模型自动升级、跨目录 / 跨机器运输或专用研究包导入导出。不同运行器不应被假定天然共享文件，实际交接由 Skill 指导外部工具完成。

同一研究的 CLI 状态变更串行，Agent 可以并行分析材料；此要求不意味着所有研究或单次调用内的网络请求必须串行。跨机器串行交接不能仅靠单机文件锁保证。

## 4. 参考工作流

### 4.1 Discovery

| 步骤 | 动作与产物 | 约束 |
| --- | --- | --- |
| 1. 规划与采集 | Agent 提交领域计划，CLI 校验、采集与基础去重 | 必须有领域；遵守固定窗口和渠道选择 |
| 2. 提名 | Agent 合并事件、命名并绑定初始证据 | 不调用 Jev；提名不是最终主题卡 |
| 3. 候选审阅 | CLI 调用 Jev，保留资格、证据状态和四维评分；Agent 选择强化调研对象 | 不允许主动跳过 Jev；不可用时记录缺失、由 Agent 接手 |
| 4. 强化调研 | CLI 执行补证计划，Agent 核查陈述、时间和证据关系 | 必须尝试跨渠道核查；允许多轮有限补证 |
| 5. 综合与交付 | Agent 提交英文主题卡，CLI 校验并形成正式交付 | 满足证据、时间、字段及数量要求；失败保留草稿 |

是否继续补证以及研究问题是否充分回答由 Agent 判断，CLI 不自行发动研究循环。强化调研后不增加第二个常规 Jev 评分阶段。

### 4.2 Named-Topic

用户指定主题 → Agent 制订研究计划 → CLI 采集 / 补证 → Agent 综合 → CLI 校验并交付报告。需要时由 Agent 追加研究计划。

此入口无需提名和候选审阅，不属于绕过 Discovery 的 Jev 要求。用户指定对象也不意味着相关说法成立。默认渠道覆盖、证据保存、窗口固定和执行恢复规则与 Discovery 一致。

以上是能力组合的参考流程，外部工作流可自行编排 Agent，但仍须满足能力输入和交付约束。具体如何通过接口检查这些前置条件见第 10 节。

## 5. 渠道、配置与降级

七个渠道均具备贡献候选的角色，以下为已选接入方向，不代表适配器已实现或服务已通过实测。

| 渠道 | MVP 接入方向 |
| --- | --- |
| X | Grok 登录认证方向；具体调用边界待细化 |
| Reddit | RSS 搜索与社区列表 |
| GitHub | REST Issues / PRs 检索，相关项目 Release 补证 |
| Hacker News | Algolia 搜索与榜单 |
| Digg | Python 直接接入公开数据接口 |
| arXiv | Python 直接接入公开 API |
| Web | Brave 搜索，并另行获取页面正文 |

全部支持渠道默认启用。Discovery 与 Named-Topic 默认尝试经 doctor 验证配置完成的全部渠道；用户可通过 CLI 参数选择所需渠道。首次研究或相关配置变化时自动运行 doctor。参数选择不能绕过配置验证，配置验证也不保证后续每次请求成功。

| 本次渠道选择与状态 | 处理 |
| --- | --- |
| 未指定渠道参数 | 默认尝试所有经验证配置完成的渠道 |
| 仅选择 X / Reddit，Reddit 失败 | 记录缺失，继续其他操作；不调用 Brave，即使 Brave 已配置 |
| 选择包含 Web / Brave，且 Brave 经验证可用 | 允许对所选渠道的专用采集失败进行定向 Web 降级 |
| Web / Brave 未配置或不可用 | 保留缺失，不能承诺兜底成功 |
| 未配置、未选择、请求失败、成功但无结果 | 分别记录，不能统一写成搜索无结果 |

间接检索须区分**内容所在渠道、实际检索方式、正文是否取得**。Brave 命中 Reddit 页面不代表 Reddit 直连成功；同一材料经直连和 Web 发现不构成两个独立来源。只有片段时如实标记，不自动启动浏览器。

未选择 / 明确禁用渠道的内容能否在普通 Web 搜索中被间接采用，尚待定义，不能把主动禁用当作故障自动替代。详见 [渠道与证据契约](source-evidence-contract.md)。

## 6. 候选资格、评分与选择

### 6.1 资格与证据状态

领域相关性、是否纯猜测、初始证据状态与研究价值分别表达，高热度或高分不能抵消资格问题。

| 情况 | 当前规则 |
| --- | --- |
| 社区纯猜测，例如某模型可能即将发布 | 排除，不作为待核实主题卡交付 |
| 缺乏具体新事项的求助、入门问答、空泛感想、纯推广或空内容 | 按语义排除；不能仅因问句或自荐形式排除实际新事件 |
| 有明确事件线索，但只有摘要或搜索片段 | 允许进入补证，记录“初始证据不足”；不等同垃圾或已确认事实 |
| 低互动的一手发布，或只有一个直接来源 | 不因互动量或来源数硬淘汰；仍须尝试跨渠道核查 |
| 同一事件的多份材料 | 由 Agent 合并并保留证据关联，不自动形成多张卡 |
| 合格主题超过卡片上限 | 由 Agent 最终选择；未入选不等同垃圾或事实被否定 |

候选状态枚举、排除原因和审计留痕的具体结构仍待设计。

### 6.2 Jev 四维 Score

四个维度为：**实质变化、具体性与信息量、潜在影响、后续研究空间**。每维采用五档语义标准，直接使用 Jev 返回的连续 Score，保留分维度结果。

- 判断依据为 CLI 取得的相关原文片段及上下文，不能把未做的强化调研当作已完成。
- 沿用已记录的评分映射：Jev 原始分为 0–4，对外以 1–5 展示时加 1，不强制舍入为整数档。
- 四维均成功返回且通过响应校验，**未舍入展示分全部 < 3**（等价于原始分全部 < 2）时，提出低价值淘汰建议，由 Agent 最终确认。
- 任一维度达到 3 仅表示未触发此建议，不保证获得补证或最终入选。没有已确认的加权总分硬淘汰规则。
- 不设置评分 unknown，不增加可评分性 Choice。概率分布与 confidence 保留供解释，不作为分数乘数或自动屏蔽合法评分的条件。
- 调用失败、超时、无效响应不能补造零分、最低分或中间分；不能因此满足四维低分条件。Jev 不可用时按规则降级，由 Agent 接手。

取消评分 unknown 不取消“初始证据不足”、事件时间未知或调用失败记录。具体五档描述、模型调用契约及阈值效果仍需样例评测；现有规则不代表评分已校准。详见 [评分设计](jev-assistance.md) 与 [候选淘汰](candidate-elimination.md)。

## 7. 证据与交付

### 7.1 证据保存

默认保存实际取得的正文文本，单独标记实际引用的片段与上下文，附原始链接、取得时间和材料类型。只有摘要、搜索片段或截断正文时如实记录，不能用 Agent 摘要补成原文。HTML 与完整 API 响应可作为可选调试资料。

强化调研必须尝试跨渠道核查，但不强制两个独立来源。一手材料可以独立支持其直接证明的事项，不能自动证明效果、比较或推广性主张；模型评分不构成新的事实证据。

JSON 保存结构化研究数据与状态，Markdown 保存主题卡与研究报告。研究状态、正文、引用、审阅及交付产物默认保留，不自动过期清理。

### 7.2 Discovery 主题卡

最终主题卡包含以下内容，具体字段名与版式尚未冻结：

1. 发生了什么：明确对象及具体事件 / 实质新进展。
2. 为何值得研究。
3. 时间及可追溯的事件时间依据。
4. 原始证据链接。
5. 已确认与待确认之处。
6. 下一步研究问题。

最终近期卡需落在固定窗口内、经过有限补证，并满足配置的卡片上限；时间始终未知的候选继续保留待核查，不能混入最终近期卡。

### 7.3 Named-Topic 研究报告

已确认交付结构化英文研究报告，组织研究问题、发现、证据与局限，允许明确说明“目前无法确认”。报告完成不等于其所有陈述都已获证实。

[报告专题](research-report.md) 建议采用 Summary、Scope and Questions、Recent Developments、Analysis and Evidence、Background、Limitations and Open Questions、Evidence References。这些章节是版式建议，未冻结为必填 schema；不为填满章节虚构发现或背景。

### 7.4 草稿与正式交付

CLI 检查可程序验证的结构、引用、时间和数量要求；Agent 负责陈述与证据之间的语义支持关系。结构校验成功不能解释为事实全部确证。

交付校验失败时保留草稿、返回具体缺口，不标记为正式交付。渠道故障、合法 Jev 降级、单一直接来源或 Named-Topic 得出无法确认，不自动构成交付失败，仍须满足其余要求。

## 8. CLI 与执行恢复

CLI 默认返回 JSON，自带供 Agent 使用的指南。研究能力需要支持计划提交与校验、采集、材料读取、Agent 产物提交、Jev 审阅和交付校验；它不从证据自行撰写研究结论。

| 执行行为 | 当前要求 |
| --- | --- |
| 重复执行相同操作 | 默认复用已有成功结果 |
| 中断后继续 | 复用成功部分，只继续失败或未完成操作，保留阶段性产物 |
| 显式刷新 | Agent 明确要求时才重新请求成功操作；固定窗口不变 |
| 健康空结果 | 属于成功结果，不为填数量反复重试 |
| 状态写入 | 同一研究串行；并行分析不等于允许并发覆盖状态 |
| 研究循环 | Agent 根据证据缺口决定是否提交下一轮计划；CLI 不自主循环 |
| 资源与故障 | 允许付费接入，不设采集次数 / Jev 费用额度；限流、故障和缺失仍如实记录 |

操作完成、渠道覆盖完整、研究问题充分回答是不同事实，不用单一“成功”掩盖缺失。

[CLI 交互草案](cli-interaction.md) 中的 `guide`、`schema`、`doctor`、`sources`、`init`、`collect`、`inspect`、`submit`、`review`、`validate`、`finalize` 均为示意命令，**尚未实现，命令名也未冻结**。返回字段、退出码、日志通道、操作身份、状态版本和冲突处理均须在接口设计中细化。

## 11. MVP 验收清单（待执行）

以下场景由已确认需求推导，作为后续验收建议；全部尚未执行。契约与恢复可用固定样例检验，渠道可用性和模型质量需真实读取 / 调用验证，二者分别记录。

- [ ] **入口与默认值**：Discovery 无领域时不能开始；默认 7 天、最多 21 张英文卡，允许不足上限；Named-Topic 可直接研究并交付英文报告。
- [ ] **窗口固定**：次日续跑、补证与显式刷新均保持原起止时间；新研究才能使用新的近期窗口。
- [ ] **事件时间**：旧发布今天转发不变成新事件；窗口外材料标记背景；时间始终未知的候选保留但不进入最终近期卡。
- [ ] **配置与覆盖**：首次研究和相关配置变化触发 doctor；两种入口默认尝试全部验证可用渠道，用户选择不绕过配置检查。
- [ ] **渠道状态**：未配置、未选择、故障和真实零结果分别记录；不能以样例通过宣称未配置渠道实测成功。
- [ ] **Brave 边界**：仅选择 X / Reddit 时故障不调用 Brave；包含可用 Web 时允许定向降级，并记录实际检索方式与正文取得程度。
- [ ] **Jev 阶段**：提名不调用 Jev；Discovery 审阅不可主动跳过；合法不可用记录允许 Agent 接手；Named-Topic 无候选审阅前置要求。
- [ ] **评分计算**：四维展示分全部 < 3 才提出低价值建议；恰好等于 3 不触发；2.99 不因展示舍入为 3 而改变判定；原始分按加 1 映射比较。
- [ ] **评分失败**：缺失 / 无效响应不补分，不触发四维低分条件；低 confidence 不生成评分 unknown；最终选择仍由 Agent 决定。
- [ ] **候选质量**：纯猜测和无具体事项的垃圾信息排除；真实事件不因问句、自荐、低互动或单一来源被机械淘汰；薄证据可进入补证。
- [ ] **核查与证据**：保留跨渠道核查尝试；一手来源只支持其直接证明的事项；正文、引用片段、摘要和 Agent 综合可区分，引用可追溯。
- [ ] **恢复与写入**：同一研究串行变更；重复执行复用成功结果和健康空结果，只继续失败 / 未完成部分；显式刷新才重取成功操作。
- [ ] **交付校验**：引用不存在、必需内容缺失、近期卡无时间依据或超过卡片上限时，保留草稿并返回缺口，不冒充正式交付。
- [ ] **不确定结论**：Named-Topic 可交付有证据与局限说明的“目前无法确认”；渠道故障或单一来源不自动阻断合规交付。
- [ ] **本地安装与协作**：Python 3.12+ 下可通过 uv tool 安装调用 CLI；默认 JSON 和内置指南可供 Agent 使用；Skill 能串起两条入口，不要求安装 Multica。

评分质量评测至少覆盖明确垃圾、薄证据、低互动一手发布和临界分数；尚无已确认的准确率、误淘汰率或延迟目标，不能虚构通过线。

## 12. 实现顺序建议

1. 定义最小 CLI 与数据契约，建立 Python 包、本地研究状态和内置指南；先验证窗口、结果复用与草稿 / 正式交付边界。
2. 实现 doctor、七渠道适配器、正文保存及受渠道选择约束的 Brave 降级；分别验证固定样例和已配置渠道的真实读取。
3. 接入 Jev 四维 Score 与候选选择记录，运行人工标注样例评测，检查阈值与误淘汰。
4. 完成 Skill 和交付模板，用宿主 Agent 跑通 Discovery 与 Named-Topic，并检验外部编排下的产物交接。

此顺序为交付建议，不表示实现已经开始或获得公共发布授权。
