# Skill、Agent 与研究 CLI 的分工

阅读入口：[MVP 规格](mvp-spec.md) · [文档索引](../README.md)。本文保留专题细节与历史提案；当前范围以主规格及后续有效决定为准。

状态：第九轮明确编排与产物传递属于 Skill 层，Multica 为当前使用方式而非必需依赖；也应允许宿主 subagent 协作。尚未实现或配置。

## 已确认边界

- 同时支持同一程序中的不同模型 / 推理档位，以及不同 Agent 程序。
- 用户自行设计工作流。Skill 指导 Agent 使用宿主可用的编排能力：当前可通过 Multica 分配任务，也可通过宿主 subagent 实现，不要求安装 Multica。
- 使用 Multica 时，任务与产物传递依赖 Multica CLI；研究 CLI 不实现上传、下载、跨机器传递或 Multica 适配器。
- Siglens CLI 提供研究能力，管理其输入、证据、产物、运行状态与校验。CLI 继续调用 Jev，Jev 不承担生成式 Agent 的角色。
- 先前提出的阶段默认能力、自动升级条件与 CLI 启动 Agent 均不属于已确认 CLI 功能。可作为未来外部工作流示例，不作为工具中的强制流程。
- 多轮研究由 Skill 指导 Agent 根据证据缺口决定继续，CLI 只执行结构化计划，不承担循环编排。
- CLI 内指南说明研究能力、输入输出与校验；Skill 说明如何编排、分配 Agent、使用外部工具传递产物。参考 Discovery 与 Named-Topic 工作流帮助用户组合研究能力。

## Multica 文档核查（2026-09-28）

官方文档描述：Agent 绑定 Runtime，可按其支持情况配置模型与推理强度；Squad 先唤醒负责人，由负责人分派成员，并在成员结果到达后继续协调。这支持把 Agent 选择留给 Multica，而不是在研究工具中重新实现。

项目资源文档明确本地目录绑定特定 daemon，任务也可能在独立 worktree 中运行。因此，“相同项目”不意味着共享上一任务的本地证据文件。这是对研究产物需要明确交接机制的设计推论，不表示 Multica 不支持附件或其他传递方式。

来源：[Agent 配置](https://multica.ai/docs/agents-create)、[Squads](https://multica.ai/docs/squads)、[项目资源](https://multica.ai/docs/project-resources)。仅核查公开文档，未验证用户实例版本与设置，也未创建任务或配置 Agent。

Multica 还提供阶段子任务与附件上传 / 下载，能作为产物运输方式；其 Run 完成不等于 Issue 完成，也不应被 Siglens 解释为研究已通过质量校验。来源：[CLI](https://multica.ai/docs/cli)、[Runs](https://multica.ai/docs/tasks)。

Squad 文档提及 stage barrier，不能断言 Multica 没有阶段或依赖能力；本次核查也不足以承诺任意 DAG 的全部语义。Siglens 的能力契约应独立于这些具体编排机制。

## 边界契约

| Skill 指导的宿主工作流 | Siglens CLI |
| --- | --- |
| 选择 Agent、模型、推理档位、运行器 | 接受结构化计划与 Agent 产物 |
| 决定下一任务、并发与任务级重试 | 执行采集、基础去重、Jev 审阅和补证 |
| 决定何时升级模型或转交他人 | 暴露材料不足、校验失败及可继续执行的信息 |
| 传递产物或其可访问引用 | 校验输入版本、证据引用和已有执行状态 |
| 管理外部 Agent 运行成本 | MVP 不控制研究额度；保留可取得的调用诊断，不虚构外部 Agent 成本 |

工作流任务重试和 CLI 调用重试不是同一层：已确认同一研究内默认复用相同操作的已有结果，只有 Agent 明确要求刷新时才重新请求；操作身份及失败重试待设计。

产物传递在 Skill 层协调：Multica 场景使用 Multica CLI，宿主 subagent 场景使用其可用的上下文或文件交接机制。研究 CLI 读写本地研究产物并校验，不为跨目录 / 跨机器交接建设专用打包、导入导出或运输能力。此前“可携带研究包 + 导出 / 导入”的提案撤回。

交接建议说明输入文件 / 内容、研究约束、待完成内容与预期结果；外部工作流负责让后继 Agent 实际取得文件，不能只传递另一台机器上的绝对路径。研究 CLI 中稳定证据 ID、格式版本、运行状态等属于数据正确性，仍可设计，但不扩展成运输协议。

同一研究的 CLI 状态变更已确定串行执行，Agent 可以并行分析材料。并发提交的冲突处理、重复操作身份判定及中断恢复仍待设计；不因传递外置就推断这些问题已解决。

能力草案见 [研究能力](research-capabilities.md)。
