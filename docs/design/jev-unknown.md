# unknown 与 Jev Score 的适配分析

阅读入口：[MVP 规格](mvp-spec.md) · [文档索引](../README.md)。本文保留专题细节与历史提案；当前范围以主规格及后续有效决定为准。

状态：历史分析，已退出 MVP 实现范围。第二十五轮 Q69 明确抛弃评分 unknown，仅使用 Jev Score，替换 Q66，并否决本文的可评分性 Choice 方案。以下保留 2026-09-28 第二十四轮的事实核查与当时提案，不作为当前要求；未调用模型或完成样例评测。当前规则见 [Jev 设计](jev-assistance.md)。

## 结论

unknown 独立于五档价值分是合理的。它表达当前材料不足以评价某一维度；五档分表达有依据时价值处于什么程度。两者回答不同问题，不能把无法判断填成最低档或中档。

需要收窄此前“材料不足即 unknown”的说法：应检查某一维度需要的材料是否缺失，而不是候选整体是否已充分核实。薄证据候选可以在部分维度有有效分数，在其他维度为 unknown。

## 官方机制与适配含义

Jev Score 根据给定有序 criteria 返回等级概率、加权均值 score 和 confidence。五档对应索引 0–4，没有独立的 unknown 返回档；把 unknown 添加为第六档会使它取得有序数值并影响均值。若展示 1–5，已有效评分的 score 加 1 映射。

confidence 来源于概率分布的集中程度。低 confidence 可能来自档位边界模糊、问题混合多个维度或材料不足；高 confidence 也不证明判断正确。因此不能用一个未经评测的 confidence 阈值来定义 unknown。

来源：[Score](https://docs.typesafe.ai/primitives/score)、[Confidence](https://docs.typesafe.ai/confidence)。这里的分数是模型对量表位置的估计，不是事实真实性或客观研究价值的已校准概率。

## 三种信息须区分

| 情况 | 表达建议 | 原因 |
| --- | --- | --- |
| 材料足以评价，但相邻档难区分 | 保留 score、分布和 confidence | 允许 3.4 等小数是 Score 的正常用途 |
| 该维关键依据缺失 | unknown，有效分数为空；标明缺口 | 防止模型被迫输出的数值进入淘汰条件 |
| Jev 调用失败、响应无效或尚未运行 | 单独执行状态，分数为空 | 这是服务 / 执行问题，不代表证据内容不足；按既有降级规则处理 |

状态和字段名尚未冻结。unknown 也不等同于整个事件“无法确认”：初始证据状态仍独立记录，评分只是基于已取得材料的初步价值评价。

## 为什么中点不能代替 unknown

以下均为解释用假设分布，不是模型实测：

- 五档概率为 0 / 0 / 1 / 0 / 0，均值是 3，模型集中选择中等。
- 五档概率为 0.5 / 0 / 0 / 0 / 0.5，均值也是 3，但判断在两端分歧。
- 五档概率均为 0.2，均值仍是 3，判断分散。

均值相同不代表依据相同。后两种分布也不能单独证明材料不足，需检查输入与评分条件；它们首先是需要 Agent 留意的不确定性信号。

## 按维度判定的例子

一篇可完整取得的公告仅说“新版已上线”，没有能力变化或使用范围：

- 具体性与信息量可以偏低：实际材料缺乏细节，这本身可观察。
- 实质变化可能 unknown：不知道新版具体改变了什么。
- 潜在影响可能 unknown：没有受影响对象、场景或可解释的后果依据。
- 后续研究空间应检查是否有明确问题及可取得的验证路径，不能只因前两项 unknown 自动给高分。

若拿到的仅是搜索摘要、正文抓取失败，则不能把未取得的全文判成信息贫乏。量表需明确评价“当前材料提供的信息”还是“事件已有的全部信息”；MVP 建议以当前绑定材料为评分对象，并显式标注仅摘要、截断等状态。涉及实际事件的变化与影响时，不用未观测信息补全结论。

对于潜在影响，可依据已公开能力与适用场景作有依据的初步评价，不要求先观察到实际普及结果；未来结果尚未发生不自动意味着 unknown。应避免以“先完成深入研究”作为候选审阅的评分前提。

## MVP 接入建议，待决定

1. CLI 检查是否有材料、引用及取得状态；明显空材料或执行失败不伪装成评分成功。
2. 在原有 Jev 候选审阅中，每维增加一个独立 Choice，判断当前材料是否足以按该维 rubric 作初步评价；并保留原有五档 Score。Choice 的文字标准说明该维需要什么信息，而不是要求模型预测自己的正确率。
3. 可在同一次请求中提交可评分性 Choice 和 Score。各问题独立回答，Score 不读取 Choice 结果；CLI 收到响应后决定数值是否有效。若需避免对不足材料计算 Score，则必须拆分请求，这是另一种方案。
4. Choice 判为不足时，对该维输出 unknown，附材料范围和缺失说明；原始 Score 若存在仅留作诊断，不参与淘汰。说明由 Agent 给出，不能要求 Choice 凭空生成自由文本理由。
5. Agent 审阅可评分性判断及分布，确认或更正状态。可评分性判断同样可能错；保留修改理由，不将额外 Choice 当作校准完成的可靠性保障。Choice 自身拿不准时交给 Agent，不直接套用默认阈值。

依据：[Choice](https://docs.typesafe.ai/primitives/choice)、[Primitives](https://docs.typesafe.ai/primitives)。上述方案增加问题数但可合并于已有审阅请求；不要求新增候选研究阶段。更精简的备选是由现有 Agent 提交每维可评分性，CLI 只对其接受的维度调用 Score；两者应在样例中比较，当前未冻结。

## 对 Q68 的影响与验证

只有四维有效分数均存在且全部小于 3，才产生低价值淘汰建议，Agent 最终确认。有 unknown 时不满足这一条件，不补零也不对其余维度求平均替代；但已确认的纯猜测、垃圾或其他资格排除仍有效，unknown 不自动保证补证名额。

样例评测应分别标注每维可评分性与可评分时的等级，覆盖真实低价值、关键信息缺失、同一证据逐步补充、相邻档模糊和模型调用失败。重点测量把有效低分误标 unknown、把缺失材料强行打分，以及由此造成的误淘汰；不能只检查均值是否看起来合理。先比对 Agent 判定与额外 Choice 的收益，再决定是否保留额外判断。
